## 목표: "사람이 직접 구현하기 힘든" 고난이도
- 장식 이펙트의 조합이 아니라 **알고리즘·수학·물리·렌더링이 핵심**이어야 한다: 유체/입자 시뮬레이션, 수치해법, 절차 생성, 솔버, 레이마칭, 기하 알고리즘 등.
- 흔한 라이브러리 호출 한 줄로 끝나는 것(GSAP 트윈 몇 개, 기본 CSS 전환)은 고난이도가 아니다. **직접 짠 시뮬레이션/솔버/셰이더가 화면을 만든다.**
- 시작하기 전에 **알고리즘을 먼저 설계**(수식·자료구조·타임스텝·경계조건)하고 구현해라. 수치 발산 방지(고정 dt, clamp, 안정 스킴)와 실제로 "그럴듯하게 보이는지"까지 검증해라.
- `meta.json` 에 난이도 증명 필드를 넣어라:
  `"hard":{"level":4,"why":"무엇이 어려운가 2~3문장(알고리즘·수치적 함정)","algo":["Stable Fluids","Jacobi 압력 풀이"],"refs":["출처 URL 또는 논문/글 제목"]}` (level 4=상, 5=최상)
- 조사한 레퍼런스(`100/research/H1~H5.md`)에 해당 항목이 있으면 읽고 구현 요점을 참고하되, 코드를 그대로 복붙하지 말고 **우리 스택·예산에 맞게 직접 구현**해라(라이선스 이슈 회피).

## 성능 예산 (검증기는 소프트웨어 렌더라 매우 느리다 — 이게 이 라운드의 최대 함정)
- 시뮬레이션 격자는 기본 **192×108 이하**(상한 256²), CPU 파티클 ≤ 6,000, GPU(FBO) 파티클 텍스처 ≤ 128×128~256×256, 렌더 스케일 ≤ 0.5(CSS로 업스케일), **프레임 캡 약 20fps**(시간 누적으로 스킵), 고정 타임스텝.
- `IntersectionObserver` + `visibilitychange` 로 화면 밖/탭 숨김 시 정지. 메인스레드 프레임 비용 ≤ 약 40ms 를 목표(그보다 느리면 스크린샷이 막혀 타임아웃).
- WebGL 부동소수점 텍스처는 `EXT_color_buffer_float`/half-float 지원을 **기능 검사**하고, 없으면 RGBA8 인코딩 또는 CPU 경로로 폴백. `getContext` 실패·컨텍스트 lost 시에도 콘솔 에러 없이 정적 포스터로 폴백.
- 오디오는 쓰지 마라(검증 불가). 외부 네트워크·이미지 에셋 금지(전부 프로시저럴). three.js(r149 전역 `THREE`)·Matter·GSAP 플러그인은 필요할 때만, **핵심 알고리즘은 직접 구현**.
- 무거운 첫 프레임 금지: 초기화에 수 초가 걸리면 시뮬을 점진 워밍업하고, 5초 안에 의미 있는 첫 화면을 보여라.

## 검증기·데모
- 검증기는 마우스를 움직이고 스크롤한다. **입력이 없어도 시간 변화가 보이도록** 자동 시나리오(가상 포인터, 주기적 드롭/충격, 자동 카메라)를 넣고, 사용자가 만지면 중단·양보해라.
- 시뮬이 "죽어서 정지"하거나 "폭발해서 화면이 비는" 상태가 되지 않게 자가 복구(리셋/재시드) 로직을 넣어라.
- 최종 스크린샷은 `Read` 로 직접 보고 **빈 화면·깨짐·잘림**을 확인해라.

## CPU 보호 (이전 라운드에서 이미 한 번 과부하가 났다)
BRIEF.md 의 '라운드 2 추가 규칙' CPU 항목을 그대로 따른다 — Bash 에 `timeout 600000`, `check.js` 는 섹션을 다 만들고 읽고 고친 뒤 **2~3개씩 묶어서만**(섹션당 최대 2~3회), 전역 락으로 직렬 실행됨(대기 정상). 임시 스크립트 파일명엔 섹션 번호를 붙여 다른 에이전트와 덮어쓰지 마라.
