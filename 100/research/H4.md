### A. 2D 광전달 (DOM이 빛을 막고 빛이 번지는 계열)

**H4-01. 2D Radiance Cascades 전역조명 — 빛나는 카드와 컬러 블리딩**
- 화면: 어두운 페이지 위에 발광 카드(네온 색)와 커서 광원이 있고, 불투명 카드 뒤로 부드러운 그림자·벽면 컬러 번짐·간접광이 실시간으로 생긴다. 광원 개수가 늘어도 비용 불변.
- 알고리즘: 장면(발광색+불투명도) 텍스처 → 캐스케이드 i 가 구간 [t_i, t_{i+1}] 의 레이 구간만 담당(t_i ∝ 2^{αi}, α=2 → 프로브 간격 2배·방향 수 4배, 캐스케이드마다 값 총량 동일). 상위→하위 병합: `M(R_{a,b},R_{b,c}) = [I_{c→b} + exp(−τ_{c→b})·I_{b→a}, τ_{c→b}+τ_{b→a}]`(= premultiplied alpha 합성, α=1−β). 반해상도 프로브 + 바이리니어 업샘플(링 아티팩트는 "Bilinear Fix"로 완화). 페넘브라 조건 Δs<∝D, Δω<∝1/D.
- 어려움: 캐스케이드 구간·프로브 격자·방향 인덱싱을 텍스처 레이아웃 하나로 맞추고, 병합 시 방향 4개 평균·가시성(alpha) 전파·링 아티팩트·구간 경계 누수를 동시에 잡아야 한다. 레이 스텝이 SDF 가 아니라 볼류메트릭이면 스텝 수 추정이 어렵다.
- 축소: 내부 해상도 ≈ 192×108(프로브 격자), 캐스케이드 4~5개(레이 4→16→64→256), 구간당 스텝 6~8, 점프 플러딩 거리장 대신 occluder 마스크 직접 샘플. 장면이 정적이면 변경 시에만 재계산 → 소프트웨어 렌더도 캡처 가능. 추정 비용: 프로브 ≈ 20k × 4 레이 × 8 스텝 × 5 캐스케이드 ≈ 3M 샘플/프레임(1초 내외, 추정).
- 난이도: ★5
- 출처: https://21st.dev/@vgpu/components/radiance-cascades.md (JFA 거리장 + 6캐스케이드 base 4 + RGBA16F + 상→하 병합, alpha 에 가시성) / https://arxiv.org/html/2408.14425v1 (Osborne·Sannikov: 구간식·병합식·페넘브라 기준) / https://odr.chalmers.se/items/3ee9fb4e-1880-46c2-802a-a660e38dc9ee (Chalmers 2025 SPWI) / https://kornel.ski/radiance (구간 계산표 RadiCalc)
- 중복: 신규

**H4-02. Holographic Radiance Cascades — 상수 비용 2D GI 변형판**
- 화면: H4-01 과 동일한 결과를 레이트레이싱 없이 구간 합성만으로. 노이즈/링 감소, 큰 장면에서 고정 비용.
- 알고리즘: 다중 레벨 프로브 + 짧은 레이 구간 결합으로 긴 레이를 합성(레이 트레이스 제거). 논문 수치: RTX3080 노트북 512²=1.85ms, 1024²=7.67ms, "2D 기준해와 시각적으로 구분 불가"(저자 주장).

**H4-03. 2D SDF 소프트 섀도 라이팅 — 카드가 던지는 반그림자와 법선 라이팅**
- 화면: 카드·버튼(둥근 사각 SDF)이 커서 광원의 빛을 가려 반그림자를 드리우고, 카드 표면은 절차적 범프 노멀로 광원에 따라 입체감이 변한다. 광원 2~3개(색 다름).
- 알고리즘: 2D 스피어 트레이싱으로 광원→픽셀 레이를 SDF(둥근 박스 합집합)에서 전진, `res = min(res, k·d/t)`(d=현재 SDF, t=진행거리)로 반그림자 폭 결정(IQ 소프트섀도: 레이마칭 최소거리가 페넘브라를 정함). 개선판은 이전 스텝 거리 ph 를 써서 계단 아티팩트 제거(추정—원문 미확인). 다광원 가산, 거리 감쇠 `1/(1+a·d²)`, 노멀은 높이장 기울기.
- 어려움: 스텝 한계 때문에 생기는 밴딩/광원 근처 아티팩트 처리, 반그림자 폭이 물리적으로 맞는 k 설정, 높이장→노멀→스페큘 일관성.
- 축소: 1/3 해상도, 광원당 24~32 스텝, 광원 ≤3. 비용 ≈ 130k px × 3 × 28 ≈ 11M SDF → 가볍다.
- 난이도: ★4
- 출처: https://www.cl.cam.ac.uk/teaching/1718/FGraphics/1.%20Ray%20Marching%20and%20Signed%20Distance%20Fields.pdf (소프트섀도 `16*d/t`) / https://arxiv.org/pdf/2210.04449 (RTSDF 소프트섀도 SDF) / IQ rmshadows 는 검색결과에서 링크만 확인(본문 미열람: https://iquilezles.org/articles/rmshadows/ — 404)
- 중복: 신규(부분 유사 s026 의 3D 소프트섀도, s033 의 CSS 마스크 손전등은 가림 연산 없음)

**H4-04. 가시성 다각형 그림자 — Canvas2D 정밀 레이캐스트 + 면광원 반그림자**
- 화면: DOM 요소 윤곽(사각형 20여 개)이 점광원(커서)에 대해 칼같은 그림자와 면광원일 때의 움/반그림자를 만든다. 벽이 움직이면 그림자 꼭짓점이 실시간 추종.
- 알고리즘: 각 사각형 꼭짓점 방향 ±ε 로 레이 3개씩 발사 → 각도 정렬 → 교차점 폴리곤(가시성 다각형). 면광원은 광원 위 샘플 12~16점 지터를 누적 합성(부분 가림 비율=알파). 지오메트리 기반 그림자는 입력이 볼록 껍질이면 umbra/penumbra 쐐기를 직접 구성 가능.
- 어려움: 정렬·ε 처리 시 틈새/떨림, 겹치는 사각형, 화면 경계 처리, 샘플 누적에 의한 밴딩.
- 축소: Canvas2D 라 GPU 불필요. 샘플 8점 + 소폭 블러. 소프트웨어 렌더에서도 문제없음(오히려 기준선).
- 난이도: ★4
- 출처: https://archive.gamedev.net/archive/reference/articles/article2032.html (WebFetch 522 실패, 검색 스니펫으로 "지오메트리 기반 점광원+반경 소프트섀도" 확인) / https://www.gamedev.net/articles/programming/graphics/dynamic-2d-soft-shadows-r3065

### B. 유리·굴절·분산

**H4-05. 리퀴드 글라스 렌즈 패널 — 색수차·프레넬·베벨 굴절**
- 화면: 둥근 알약 모양 유리 패널이 배경 텍스트/이미지 위를 드래그하면 가장자리에서 배경이 휘고, 빨강/파랑이 갈라지고, 림에 하이라이트와 그림자가 생긴다. 패널끼리 겹치면 아래 패널이 위 패널에 굴절된다.
- 알고리즘: 둥근 사각 SDF `d` → 가장자리 `bevelWidth` 안에서 높이 프로파일 `h(d)`(구형 볼록/ squircle) → 법선 `n = normalize(∇h, 1)` → `refract(-V,n,1/ior)` 오프셋으로 배경 FBO 샘플. 색수차: R/B 를 굴절 벡터 양쪽으로 `±ca·len(offset)` 분리(가장자리 최대, 평탄부 0). Fresnel `F = F0+(1−F0)(1−cosθ)^5`, 멀티 라이트 스페큘, 가우시안 블러(frost). 레이어 합성: 완성된 유리를 캔버스에 되써서 다음 유리가 굴절.
- 어려움: "DOM 배경 읽기" — 외부 라이브러리는 html2canvas·자체 래스터라이저 사용(중앙값 55.5ms 캡처). 우리는 에셋/라이브 DOM 캡처 없이 **배경을 셰이더가 직접 절차 생성**해야 함. 굴절 오프셋이 패널 밖 샘플로 나갈 때 클램프 처리, 가장자리 아티팩트.
- 축소: 렌더 스케일 0.5, 색수차 3탭, 블러 5탭 가로세로 분리. 패널 3개. 비용 낮음 — 소프트웨어 렌더에 적합.
- 난이도: ★4

- 중복: 신규(부분 유사 s021 굴절 파문, s022 RGB 분리 — 대상이 "패널 SDF + 물리 굴절"이라 다름)

**H4-06. 멀티사이드 굴절 보석 — 후면 법선 패스 + 채널별 IOR**
- 화면: 절단면이 있는 보석/다이아가 회전하며 내부에서 빛이 몇 번 꺾여 무지개가 번지고 면마다 반짝임이 바뀐다.
- 알고리즘: ① 후면(backface)을 법선 텍스처에 렌더 ② 전면에서 `refract` 1회 → 후면 법선 샘플 → 내부 반사/2차 굴절(전반사 `|sinθ|>1` 분기) ③ 채널별 IOR(예 R 2.40/G 2.42/B 2.44)로 3번 계산 ④ Fresnel 반사 + 프로시저럴 환경맵 반사. MeshTransmissionMaterial 처럼 노이즈 기반 블러가 없으면 RGB 밴딩이 생김(포럼 확인).
- 어려움: 환경맵을 외부 HDR 없이 만들어야 하고(캔버스로 스튜디오 라이트 큐브맵 합성), 내부 바운스 수·전반사 분기 때문에 면별로 비주얼이 급변.
- 축소: 스케일 0.4, 바운스 2회, 채널 3×. three r149 `WebGLRenderTarget` 2개. 폴리곤 수 ≤ 200.

**H4-07. 2D 프리즘 스펙트럼 분산 — 백색광이 무지개로 갈라지는 광학 벤치**
- 화면: 어두운 배경에 백색 빔이 삼각 프리즘을 통과하며 부채꼴 무지개로 퍼진다. 프리즘을 드래그하면 각도에 따라 스펙트럼이 변하고 전반사에서 사라진다. 렌즈·직사각 유리 블록 모드.

**H4-10. 풀장 코스틱과 구체 — 높이장 물 시뮬 + 면적비 코스틱**
- 화면: 타일 풀장 바닥에 흔들리는 코스틱 빛 그물이 맺히고, 구체가 물에 떠서 드래그로 파문을 만들며, 수면에서 굴절·반사가 보인다.
- 알고리즘: 높이장 `∂²h/∂t² = c²∇²h − 감쇠`(float 텍스처 ping-pong, 법선 저장). 코스틱: 수면 메시 정점마다 굴절 광선을 바닥으로 투영해 `oldPos`/`newPos`(`refract(-light,normal,1/1.333)`), 프래그먼트에서 `oldArea/newArea` = `length(dFdx)*length(dFdy)` 비 → 삼각형이 작아질수록 밝아짐. 구체 그림자는 시그모이드 블롭, 풀 림 가림은 `intersectCube`. 수면 쉐이딩은 레이–풀 큐브 교차 후 굴절/반사 선택(프레넬).

**H4-12. GPU FFT 바다 — Tessendorf 스펙트럼, 변위·법선·거품**
- 화면: 거대한 파고의 바다가 실제 파도 스펙트럼으로 움직이며 파도 마루가 앞으로 쏠리고(choppy displacement) 거품이 생기고 석양이 반사된다.
- 알고리즘: Phillips/JONSWAP 스펙트럼 `h0(k)` → 시간 진화 `h(k,t)=h0 e^{iωt}+h0* e^{-iωt}` → 역FFT(버터플라이 로그N 패스 × 가로세로) → 높이/변위/기울기 3 텍스처 → 법선·야코비안(거품) → 반사·굴절·SSS. 2캐스케이드 주파수 분할(예 256 + 소 캐스케이드).

**H4-13. 비누방울 군집 — 박막간섭 무지개, 두께 흐름, 터짐**
- 화면: 비눗방울 5~7개가 떠오르며 표면에 파랑·자주·황금 소용돌이 무지개가 흐르고, 위쪽이 얇아져 검은 점이 생기다 터진다. 스튜디오 조명이 반사된다.

- 어려움: 두께 장이 시간에 따라 흘러야 하며(곡선 노이즈 + 중력 배수) 시각적 자연스러움이 파라미터 의존적, 박막 곡선이 물리적으로 맞지 않으면 "그냥 무지개 그라디언트"로 보임.

- 어려움: 결과가 이산적으로 갈리는 광선(인접 광선의 ~9.8% 가 다른 결과로 분류 — 128×72 격자 실측) → 가장자리 노이즈, 적분 스텝 수와 정확도 트레이드오프, 원반 shear 가 시간에 따라 감기는 문제(두 에포크 크로스페이드).
- 축소: 스케일 0.25~0.3, 스텝 190→64(고정 스텝 + 적응형 가속), 지터 4프레임, 별은 해시 셀 점으로 절차 생성. 비용 ≈ 60k px × 64 ≈ 4M 적분/프레임.

- 알고리즘: 스플랫마다 위치·스케일·쿼터니언·색·불투명도 → 공분산 `Σ = R S Sᵀ Rᵀ` → 화면 투영 `Σ' = J W Σ Wᵀ Jᵀ`(2×2, EWA; 수식은 추정—검색 미수행) → 고유벡터로 쿼드 크기 결정 → 프래그먼트에서 `α = o·exp(−½ dᵀ Σ'⁻¹ d)`. 정렬: 카메라 깊이 기준 CPU(웹워커) 기수 정렬(원 저자: 100만 개 ≈150ms, 정렬 ≈4fps, 렌더 60fps; GPU 비토닉은 WebGL1 에서 느림). 블렌딩: 뒤→앞 프리멀티플라이드 알파.
- 어려움: 정렬 비동기로 인한 일시 아티팩트, 공분산→2D 변환 수학, 투명 누적 순서. 대량 쿼드 래스터화 비용.
- 축소: 스플랫 20k, 정렬은 메인 스레드 카운팅 정렬(각도 변경 임계 때만), 스케일 0.4, 쿼드 최대 크기 클램프. 소프트웨어에서 쿼드 오버드로우가 병목(추정).

**H4-35. 얼음 크리스털 동굴 — Voronoi 균열, 내부 굴절·표면 하하 산란**
- 화면: 푸른 얼음 덩어리 내부에 균열 면이 겹쳐 있어 광원이 움직이면 균열 면마다 반사와 굴절이 다르게 번쩍이고, 두꺼운 곳은 짙은 청록, 얇은 곳은 투명.
- 알고리즘: 3D Voronoi(F1/F2 차)로 균열 면 법선 소량 섭동, 레이마칭 SDF 진입 후 내부 `refract` + 두께 기반 흡수(Beer–Lambert, 청록 편향), 균열 면 프레넬 반사. 눈 SSS 질감은 두께 샘플.
- 어려움: 균열 법선의 시각적 일관성, 내부 마칭 분기, 얼음 블루 톤 에너지 균형.
- 축소: 스케일 0.3, 외부 40스텝 + 내부 16스텝, Voronoi 27셀 대신 8셀 근사.

## 6. 위험·주의

- **float RT / 파생(dFdx)**: H4-09·10·12·14·20·29 는 float RT 의존. 소프트웨어 렌더 실측 전에는 폴백(RGBA8 패킹)을 포함해 설계.
- **스텝 수 외부 노출**: 모든 레이마칭 후보는 `?steps=`, `?scale=` 를 받아 검증 환경에서 낮출 것. 원본 대비 축소는 비주얼 열화가 있으므로 "고화질 모드 / 검증 모드" 이원화.
- **누적·시간 고정**: H4-26·29 는 누적 프레임 수와 시드를 URL 로 고정해 캡처 재현성 확보.

- **라이선스**: Shadertoy 계열은 CC BY-NC-SA — 구조·수식만 참고하고 코드는 새로 작성. 아이디어/알고리즘 자체는 자유.
