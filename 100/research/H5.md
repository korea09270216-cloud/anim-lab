## 1. 새로 알게 된 2025~26 흐름 (출처 있는 것만)

1. **Pretext (Cheng Lou, 2026-03-27)** — DOM 리플로우 없이 텍스트 줄바꿈을 계산하는 15KB 라이브러리. `layoutNextLine(prepared, cursor, maxWidth)` 가 줄마다 폭을 바꿀 수 있어 **장애물 주위로 흐르는 텍스트**가 60fps 로 된다. 'Bad Apple 텍스트 랩'이 X 에서 바이럴됐다. (A 그룹)
2. **HTML-in-Canvas (WICG, Chrome 146+ 플래그 / 148~150 origin trial)** — 실제 DOM 을 캔버스·WebGL 텍스처로 그린다. Canvas UI(canvasui.dev)가 35개 효과(서리·물방울·천·파편 등)를 내놨다. 우리 환경에선 못 쓰므로 **절차적으로 그린 페이지 텍스처로 대체**해 같은 셰이더 효과를 만든다. (B 그룹)
3. **Slug 알고리즘 특허 퍼블릭 도메인 (2026-03-17)** — GPU 가 베지어 아웃라인에서 직접 글자를 래스터화. (D01)
4. **WebGPU compute 데모** — MLS-MPM 유체(10만~30만 입자), 3D Physarum, Particle Life, 2D GI. 우리는 WebGPU 검증 불가라 WebGL2 부동소수 텍스처 / CPU 축소판으로 대체한다. (C 그룹)
5. **CSS 가 게임 엔진이 됨** — cssDOOM(2026). 3D 변환 div 수천 개 + `shape()` + `atan2/hypot`. (E 그룹)
6. **3D Gaussian Splat 의 웹 상용화** — World Labs Spark 2.0(2026-04-14, WebGL2, three.js). 스플랫 단위 디졸브·홀·변위. (G01)

### A. 텍스트 레이아웃 물리 (Pretext 계열)

#### H5-01 에디토리얼 엔진 — 드래그 오브를 피해 흐르는 다단 본문 [S]
- 화면: 신문 지면에 빛나는 오브 2~3개가 떠다니고 드래그할 수 있다. 본문·헤드라인·풀쿼트가 오브를 만나면 갈라져 양옆으로 흐르고 단이 이어진다. 전부 실시간.
- 핵심 알고리즘: ① 단어·공백 폭을 `canvas.measureText` 로 1회 캐시(Pretext 의 `prepare`). ② 행(y 밴드)마다 장애물 원의 코드 구간 `cx ± sqrt(r² − dy²)` 을 구해 단 폭 `[L,R]` 에서 빼 **자유 슬롯 목록**을 만든다. 최소 폭 미만 슬롯은 버린다. ③ 슬롯을 왼쪽부터 `layoutNextLine(cursor, slotWidth)` 로 채우고 커서를 이어간다. ④ canvas `fillText` 로 그린다. Pretext README 의 `layoutNextLine`/`layoutNextLineRange` 가 호출마다 `maxWidth` 를 받는다고 명시돼 있다.
- 왜 어렵나: 한 행이 장애물 때문에 **둘 이상의 조각**으로 갈라지는 처리, 장애물이 움직일 때 행 단위로 텍스트가 튀는 현상(히스테리시스 필요), 한글 `keep-all` 어절 줄바꿈, DOM 재측정 없이 60fps.
- 소프트웨어 렌더 축소: Canvas2D 만 사용. 본문 300~500자, 오브 2개, 2단. 프레임당 행 30개 수준이라 무겁지 않다. **헤드리스 안전.**
- WebGPU 대체: 해당 없음(CPU/Canvas2D).

#### H5-02 실루엣 텍스트 랩 — 움직이는 흑백 실루엣을 따라 흐르는 문단 ('Bad Apple') [S]
- 화면: 흑백 영상의 검은 실루엣 모양으로 문단이 비워지고, 실루엣이 움직이면 글자가 물결처럼 밀려 흐른다. 2026-03 말 X 에서 바이럴(사용자 Kevin).
- 핵심 알고리즘: 프레임마다 실루엣을 저해상도 마스크(예: 96×54)로 래스터화 → 텍스트 행마다 마스크를 스캔해 **빈 구간 run-length** 를 슬롯으로 변환 → H5-01 과 같은 `layoutNextLine` 루프. 에셋이 없으므로 실루엣은 **절차적 애니메이션**(춤추는 메타볼 인형, 회전하는 2D SDF 도형 군집)으로 대체. (슬롯 선택 안정화·모폴로지 평활은 추정)

#### H5-04 Knuth–Plass 정렬 + 강(river) 시각화 — 폭을 끌면 단어가 줄 사이를 이동 [S]
- 화면: 같은 문단 3개를 나란히(CSS 탐욕 정렬 / 하이픈 / Knuth–Plass 최적 정렬) 보여주고 폭 슬라이더를 끌면 단어들이 줄 사이를 날아 이동한다. 단어 간격이 세로로 이어지는 '강'이 붉게 표시된다.
- 핵심 알고리즘: Knuth–Plass total-fit — box/glue/penalty 모델, 활성 노드 리스트 DP, `demerits=(1+100·badness³+penalty)²`, 글루 신축. 하이픈은 소형 패턴/음절 휴리스틱(외부 사전 없음). 폭 변화 시 이전·이후 줄 배치의 단어 좌표를 FLIP 식으로 보간. 강 검출: 인접 3줄 이상에서 단어 간 공백이 x 로 겹치는 구간. (DP 세부는 일반 지식=추정, 데모 존재는 출처 서술)
- 왜 어렵나: 조판 DP 자체, 하이픈 처리, 폭 연속 변화 중 줄 배치가 불연속 점프하는 것을 애니메이션으로 이어붙이는 일.
- 소프트웨어 렌더 축소: 영문 120단어, Canvas2D/DOM span. 안전.
- WebGPU 대체: 해당 없음.

#### H5-06 서리 — 얼음막이 커서 열에 녹았다가 다시 어는 페이지 [S]
- 화면: 페이지 전체가 성에 낀 얼음에 덮여 흐릿하다. 커서가 지나간 곳이 투명하게 녹고, 시간이 지나면 결정이 가장자리부터 자라 다시 언다.
- 핵심 알고리즘: 서리량 필드 F∈[0,1](256² 핑퐁). 커서가 가우시안으로 F 를 깎는다. 재결빙은 이웃 F 에 비례해 자라는 **이방성 셀룰러 오토마타(Reiter 눈결정 모델식 6방향, 추정)**. 렌더: F 에 비례해 페이지 mip 블러 샘플, ∇F 로 법선 → 굴절 오프셋 + 가장자리 하이라이트, 결정 노이즈 질감. (알고리즘은 추정, 효과 서술은 canvasui.dev)
- 왜 어렵나: 결정이 자연스럽게 자라는 패턴(수지상), 녹는 경계의 굴절과 하이라이트, 고해상도 필드 갱신 비용.
- 소프트웨어 렌더 축소: 필드 160×90 Float32Array CPU 갱신 + 캔버스 업스케일 블러. WebGL 시엔 128² 핑퐁.
- WebGPU 대체: 불필요(WebGL2 float 텍스처 또는 CPU).

#### H5-07 물방울 창 — 미끄러지고 합쳐지는 물방울이 페이지를 굴절 [S]
- 화면: 유리창에 빗방울이 맺혀 흘러내린다. 방울이 합쳐지고 꼬리(트레일)를 남기며, 방울 안에서 뒤쪽 페이지가 뒤집혀 보인다.
- 핵심 알고리즘(출처 서술): CPU 가 방울을 생성·이동(stick-slip 중력)·병합 → Canvas2D 로 **64×64 물맵**에 인코딩(법선 R·G, 두께·하이라이트 B, 형태·가장자리 A; 사전 계산 텍스처 255종 = 깊이 51단계 × 하이라이트 5단계) → 프래그먼트 셰이더가 법선 복원 후 굴절 오프셋·프레넬·하이라이트·소프트 섀도. raindrop-fx 는 중력 2400px/s, 증발, 트레일 파라미터, 배경 사전 블러 3~4단계, 2000방울에서 프레임 6ms.
- 왜 어렵나: 방울 병합·꼬리 분리 물리를 자연스럽게 하는 튜닝, 법선 맵 기반 굴절에서 가장자리 왜곡이 깨지지 않게 하는 것.
- 소프트웨어 렌더 축소: 방울 150개, 해상도 480×270, 굴절은 CPU `ImageData` 루프 또는 WebGL 한 패스. 가능.
- WebGPU 대체: 원래 WebGL2.

#### H5-25 cssDOOM — 섹터·벽·바닥을 div 3D 변환으로 렌더하는 레벨 [S]
- 화면: 둠 레벨 안을 걷는다. 벽·바닥·천장·문·리프트·스프라이트가 전부 `<div>`. 문은 CSS 트랜지션, 투사체는 CSS 애니메이션.
- 핵심 알고리즘(출처): 정점 좌표·바닥/천장 높이를 CSS 커스텀 프로퍼티로 넘기고, 벽 폭은 `hypot()`, 회전은 `atan2()` 로 CSS 가 계산. **카메라가 없으므로 월드를 플레이어 반대로 이동**(`--player-x/y/z/angle`). 바닥은 X축 90° 회전 div 를 `clip-path: polygon()` / `path()` / `shape()` 로 잘라 비직사각 섹터와 구멍을 표현. 스프라이트는 빌보드, 반전은 `scaleX`, 애니는 `steps()`. 섹터 밝기는 `--light` + `filter: brightness()`. 수천 개 3D 요소 컬링은 JS 가 몇 프레임마다.
- 왜 어렵나: 좌표계 변환(축 교환·부호), 컬링 없이는 브라우저가 못 버팀(iOS Safari 크래시 보고), 하늘 벽 처리, 리프트의 CSS/JS 동기.
- 소프트웨어 렌더 축소: **소형 맵(방 3개, 벽 ~40장)** 과 3D CSS. CSS3D 는 소프트웨어 합성기에서도 동작하지만 요소 수 한도(150개 이내)를 둬야 한다(추정).

- 화면: 수천 개의 반투명 타원이 모여 입체 형상(토러스 매듭·지형)을 이룬다. 포인터로 회전하면 시점이 바뀌고, 스크롤하면 스플랫이 노이즈 경계를 따라 흩어지며 사라진다.
- 핵심 알고리즘(Spark 서술+추정): 각 스플랫 = 위치·스케일·회전(공분산 Σ=R S Sᵀ Rᵀ) + 색 + 불투명도. 화면 투영은 원근 야코비안으로 2D 공분산 → 타원 이차식, 인스턴스 쿼드 + 가우시안 알파, **뒤→앞 정렬**(CPU 정렬 몇 프레임마다). 디졸브/리빌/홀은 스플랫별 노이즈 임계 + 스케일 축소 + 드리프트(Spark 예제 목록: Splat Reveal/Dissolve Effects, Interactive Holes, Particle Simulation). Spark 는 WebGL2·three.js, 2.0 에서 스트리밍 LoD.
- 왜 어렵나: 공분산 투영 수학, 대량 정렬, 알파 합성 순서.
- 소프트웨어 렌더 축소: 절차적 스플랫 6천 개, 320×180, 정렬은 JS typed array. WebGL2 인스턴싱 또는 Canvas2D 타원.
- WebGPU 대체: 불필요(Spark 자체가 WebGL2).
- 난이도 ★5
- 출처: https://github.com/sparkjsdev/spark , https://sparkjs.dev/examples/ , https://radiancefields.com/world-labs-previews-spark-2.0
- 중복: 없음

#### H5-32 MSDF 텍스트를 먼지·꽃잎으로 분해 — 3D 텍스트 파괴 [P]
- 화면: 3D 글자가 노이즈 전선을 따라 먼지와 꽃잎으로 분해돼 날아가고, 반대로 모여 복원된다.
- 핵심 알고리즘(추정): MSDF 평면/압출 텍스트, 디졸브 임계 노이즈, 경계에서 입자 생성(먼지=점, 꽃잎=곡면 평면 인스턴스 + sin 퍼덕임). 출처는 Codrops 두 편의 제목·부제만 확인: "Interactive Text Destruction (WebGPURenderer+TSL, 2025-07-22)", "Gommage Effect (2026-01-28)".
- 왜 어렵나: 분해 경계와 입자 방출의 동기, 꽃잎 인스턴스의 회전·퍼덕임, 복원 애니.
- 소프트웨어 렌더 축소: 입자 8천 개, three r149 Points + 인스턴스 평면 300개. 글자는 canvas 텍스트에서 점 샘플.
- WebGPU 대체: TSL/WebGPU 를 WebGL ShaderMaterial 로 치환.
- 난이도 ★4
- 출처: https://tympanus.net/codrops/2025/07/22/interactive-text-destruction-with-three-js-webgpu-and-tsl/ , https://tympanus.net/codrops/2026/01/28/webgpu-gommage-effect-dissolving-msdf-text-into-dust-and-petals-with-three-js-tsl/

### H. 포인터 기반 '마술'

#### H5-33 엑스레이 유체 리빌 — 커서가 유체 마스크로 살을 벗겨 해골층을 드러냄 [S]
- 화면: 육각 격자에 사람 형상 12개가 서 있고, 커서가 지나간 자리가 유체처럼 번지며 해골(엑스레이)층이 드러난다. 가장자리가 프레넬로 빛남.
- 핵심 알고리즘(출처): 마우스 궤적 2D 캔버스 → **핑퐁 유체 시뮬**(FBM 노이즈로 난류 변위) → 두 InstancedMesh 장면(솔리드/스켈레톤) 합성 마스크, 스켈레톤은 Fresnel 머티리얼, 블룸+스캔라인+그레인 후처리. WebGL 브랜치 존재.
- 왜 어렵나: 두 장면 렌더타깃 합성, 유체 마스크의 경계 질감, 인스턴싱 대량 배치.
- 소프트웨어 렌더 축소: 3D 대신 **절차적으로 그린 두 2D 레이어**(살/골격 도식) + 128² 마스크 확산. 3D 는 인스턴스 12개 three r149.
- WebGPU 대체: 저장소에 WebGL 브랜치 있음.

#### H5-34 픽셀→복셀 낙하 — 영상 한 프레임이 복셀 비로 쏟아짐 [P]
- 화면: 영상(또는 애니메이션) 프레임이 픽셀화돼 입체 복셀로 압출되고, 물리 엔진에 의해 아래로 떨어져 쌓인다.
- 핵심 알고리즘(Codrops 요약 + 추정): 프레임 다운샘플 → 복셀 InstancedMesh 높이=휘도 → 낙하는 Rapier 강체. 우리 버전: Rapier 대신 **열 단위 낙하+바운스+회전 스프링의 가짜 물리**, 소스 프레임은 절차적 애니메이션 캔버스.
- 왜 어렵나: 수천 인스턴스 물리와 렌더 동기, 쌓이는 모양의 안정성.
- 소프트웨어 렌더 축소: 48×27=1296 복셀, three r149 InstancedMesh.
- WebGPU 대체: 해당 없음.

#### H5-35 실제 물감 혼색 — 파랑+노랑=초록이 되는 서브트랙티브 페인트 [P+E]
- 화면: 커서로 안료를 문지르면 RGB 평균이 아니라 실제 물감처럼 섞인다(파랑+노랑=초록, 빨강+파랑=보라 탁색). 번짐이 유화처럼 층을 이룬다.
- 핵심 알고리즘(추정): **Kubelka–Munk 안료 혼합**(Mixbox 식 잠재공간) — 색을 4~7개 안료 농도 벡터로 보관하고 혼합은 농도 가중합 후 반사율→RGB 변환. 이류는 속도장으로. 출처는 CodePen 'Generative Ink Blobs'(2026-01)가 유화 혼색처럼 보인다는 서술까지.
- 왜 어렵나: 안료 농도 ↔ RGB 변환의 비선형성, 번짐과 혼색의 결합, 알베도 보존.
- 소프트웨어 렌더 축소: 256×144, 안료 4종, JS CPU. 가능.
- WebGPU 대체: 불필요.

#### H5-36 페로플루이드 스파이크 — 자석 아래 솟는 검은 액체 가시 [E]
- 화면: 검고 반짝이는 액체 표면이 커서(자석) 아래에서 육각 격자로 가시처럼 솟는다. 자석을 멀리하면 부드럽게 가라앉는다.
- 핵심 알고리즘(추정): Rosensweig 불안정 — 자기장 세기 B 가 임계 Bc 를 넘으면 높이장에 육각 스파이크 격자(진폭∝(B−Bc))가 생긴다. 높이장 레이마칭(또는 법선 맵) + 검은 금속 스펙큘러/환경 반사.
- 왜 어렵나: 스파이크 격자 형성을 물리적으로 그럴듯하게 모사(위상 전이), 반사 렌더.
- 소프트웨어 렌더 축소: 높이장 160×90, 저해상도 레이마칭 또는 스크린스페이스 법선 + 스펙큘러. 가능(추정).
- WebGPU 대체: 불필요.

- 출처: 없음 (추정 — 검색 예산 소진으로 미조사)

#### H5-37 비누막 박막 간섭 — 흐르며 변하는 무지개 막 [E]
- 화면: 비누 거품 표면에 얇은 막 간섭색(분홍·초록·보라)이 소용돌이치며 흐르고, 위쪽이 얇아져 검게 터지기 직전 모양이 된다.
- 핵심 알고리즘(추정): 막 두께장 h(x,y,t) — 마랑고니 흐름(저해상도 유체) + 중력 배수로 위가 얇아짐 → 파장별 간섭 `2·n·h·cosθ` 을 3~8개 분광 샘플로 계산해 RGB 로 변환.
- 왜 어렵나: 분광 간섭의 색 정확도, 두께장 시뮬 안정성.
- 소프트웨어 렌더 축소: 구 하나, 256² 두께장. 가능.
- WebGPU 대체: 불필요.
- 난이도 ★4
- 출처: 없음 (추정)
- 중복: 없음

#### H5-38 4점 호모그래피 — 라이브 DOM 카드를 네 모서리 드래그로 원근 변형 [S]

### J. 수학적 '와'

#### H5-39 맨델브로 무한 줌 — 배정밀도 에뮬레이션 [E]
